# LLM 101 curriculum update recommendations

Research date: 2026-09-07. This report compares the university syllabi and book reviews in this directory with the repository as observed during research. Its proposal table is retained as the historical research snapshot; the implementation status below records what was subsequently shipped.

LLM 101 already has a coherent audio-first path: 30 lessons in 13 units, 13 runnable labs, complete text alternatives, authored quiz feedback, local learner progress/notes, and a bounded extractive teaching-assistant capstone. The first six lesson indices in `course.js` must remain stable for existing notes and bookmarks. The gaps below describe the depth and structure gaps found at the research snapshot, rather than evidence that the sequence was missing its core story.

## Structural improvements identified at the research snapshot

The reviewed courses make prerequisites, readings, assessment, and project checkpoints visible. LLM 101 can add optional metadata to each lesson object in `course.js`—prerequisite lesson indices, estimated time, reading links, evidence tier, and a learner-facing success check—without changing the authored text or progress keys. Keep full text alternatives beside any audio addition and preserve keyboard operation, visible focus, contrast settings, browser-voice fallback, and user-controlled narration.

At the research snapshot, the first six zero-based lesson entries (indices 0–5) did not carry authored recall fields, although `app.js` supplied the existing generic recall fallback. The implementation pass added lesson-specific recall prompts while preserving those indices and existing notes/bookmarks.

Labs should continue to be shared by the browser and `labs.mjs`. Each new scenario should have a deterministic tiny fixture, an expected result, a troubleshooting explanation, and a text-only path. Avoid dependencies on paid APIs, credentials, remote model downloads, tracking, or learner microphone/camera collection. Record whether a result is a calculation, an offline toy measurement, or a real service measurement.

The university material also supports a clearer distinction among three layers that are currently adjacent: (1) mathematical/model mechanics, (2) evidence-grounded application behavior, and (3) deployment and safety decisions. A short “where this appears” line in each lesson and lab can make those transitions explicit while retaining the existing 13-unit order.

## What not to infer from the research

The public student record is sparse and self-selected. Several class dossiers have no reliable course-specific student review, and instructor-rating pages often cover different courses. Those absences are preserved in the class files. Course syllabi also vary from implementation courses to paper seminars, so their project scale and prerequisites should inform options rather than become mandatory requirements for the beginner-facing path.

The 2015 Goldberg Primer, Nielsen, and Eisenstein drafts are strong accessible foundations for representation, optimization, sequence models, and evaluation. They do not teach modern decoder-only Transformers, scaling, current alignment, RAG, or serving. The newer course pages and the other book dossiers supply those missing directions, with their own evidence tiers and publication dates.

## Implementation status

The eight priorities in this report are implemented in the current course tree. `course.js` adds the authored walkthroughs, worked examples, metadata, and recalls; `labs.js` adds deterministic result fields and fixtures; `app.js`, `index.html`, and `style.css` render lesson guides plus labeled lab inputs, summaries, evidence notes, and expandable structured traces.

| Priority | Current status | Boundary |
|---|---|---|
| 1 | Implemented: token IDs, subword and unknown-token examples, next-token targets, embedding lookup, and count-versus-learned comparison. | Fixed local fixture; not a downloaded tokenizer or trained LLM. |
| 2 | Implemented: Q/K/V shapes, positional inputs, raw and 1/sqrt(d_k)-scaled scores, causal mask row, residual, normalization, MLP, and logits in the decoder trace. | Small deterministic tensors; no model download. |
| 3 | Implemented: n-gram overlap, contamination effect, subgroup slices, calibration bins, and dataset version fields. | Tiny authored diagnostic fixture; no broad fairness or population calibration claim. |
| 4 | Implemented: lexical and fixed-vector rankings, evidence reranking, source spans, threshold abstention, source-version provenance, and capstone decision record. | Fixed concept vectors; source version is carried with the selected evidence and exercised in the cache trace, while ranking uses lexical/vector/coverage scores; bounded extractive assistant remains required. |
| 5 | Implemented: LoRA, a full-fine-tuning capacity baseline, preference objective comparison, and reward-hacking fields. | The full fit is a closed-form toy capacity comparison, not matched-budget optimization; no GPU language-model post-training. |
| 6 | Implemented: temperature/top-k/nucleus probe and three-row serving worksheet with memory and throughput/quality proxies. | Calculations and proxies are labeled; no production benchmark claim. |
| 7 | Implemented: prompt-injection, unsupported-citation, malformed-tool, canary, rollback, and cache trace fields. | Tiny authored safety fixtures; no production security guarantee. |
| 8 | Implemented: required bounded capstone plus optional Track A fixed-vector/reranked retrieval decision record. | Track B local generative adapter/conversational tutor remains future and separately scoped. |

The current implementation preserves the historical boundaries: local-only execution, complete text alternatives, user-controlled narration, existing localStorage keys, original lesson indices 0–5, and no credentials, paid APIs, tracking, learner microphone/camera collection, or model downloads. Retrieval now admits only valid authored source snapshots at or before its fixed retrieval snapshot, ranks by relevance, and uses freshness only as an equal-relevance tie-break; selected source versions remain visible for provenance and cache invalidation. The updated text changes the content-plan hash, so stale narration is invalidated by the existing preparation pipeline; narrator service readiness and completion of all regenerated recordings remain separate states.

## Verification boundary

The proposal table above records the research snapshot and should not be read as a claim that the current tree is unimplemented. Runtime behavior is verified in the repository’s `VERIFICATION.md`; the implementation pass ran syntax checks, 28 Node tests, direct updated-lab smoke calls, and the browser curriculum suite. Full speech-model regeneration and complete acoustic review remain outside that verification boundary.
